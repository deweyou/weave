# 验证与证据

从工作区根目录运行。按实际改动选择检查，结果注明提交 / 差异、平台、命令、退出码及未验证项；不要长期写死测试数量。

## 可点击区域的指针验收

所有涉及按钮或可点击区域的 UI 改动，必须按 [设计约定](../DESIGN.md#可点击区域的光标全局约定) 检查 pointer（手型）：

- 在 macOS 上实际移入图标中心、文字和完整点击热区边缘，均应显示手型；有指针的 iPad 场景检查对应交互反馈。
- 检查按钮、菜单触发器、导航项、卡片、链接、开关、原生编辑器内嵌控件和浮层操作，不能仅凭 SwiftUI 修饰符或编译通过判定生效。
- 移入禁用控件或不可点击背景不应显示操作手型；文本输入、选区和调整大小区域保留各自语义光标。
- 移出、隐藏、删除、切换页面、Toast 自动消失或点击关闭后不残留手型；相邻控件之间移动保持正确。
- 确认光标处理不拦截点击，不抢键盘焦点，不影响文本光标和选择。无法通过工具实际验证指针外观时，明确记录待人工验证，不写成已验收。

## 自动检查

| 影响范围 | 命令 / 检查 | 能证明什么 |
| --- | --- | --- |
| Swift 格式 / 静态风格 | `swift format lint --recursive --strict --configuration .swift-format Sources Tests UITests Package.swift` | Swift 源码符合仓库格式与基础静态规则 |
| Swift 行为 / 数据修改 | `swift test` | 现有测试覆盖的规则、存储与桥接行为 |
| Mac 代码与共享代码 | `xcodebuild -project Weave.xcodeproj -scheme Weave -destination 'platform=macOS' -derivedDataPath .build/xcode CODE_SIGNING_ALLOWED=NO build` | Mac target 编译 |
| iOS 代码与共享代码 | `xcodebuild -project Weave.xcodeproj -scheme Weave -destination 'generic/platform=iOS Simulator' -derivedDataPath .build/ios CODE_SIGNING_ALLOWED=NO build` | iOS Simulator target 编译 |
| 文档 / 配置 | 本地链接、入口、源码一致性；Harness `config_inspect` | 文档和配置有效，不证明 App 行为 |
| 交付差异 | `git diff --check`；暂存后 `git diff --cached --check` | 空白与差异检查，未跟踪文件需另查 |

首次使用需 Xcode / Swift 6.2 兼容工具链。沙箱中的宏插件或编译缓存权限失败属于环境问题；明确报告并走宿主授权，不把关闭沙箱作为仓库默认命令。日志和构建产物放 `.build/` 或任务临时目录，Run 中按需记录 Evidence。

Mac 实际预览使用 `xcodebuild -project Weave.xcodeproj -scheme Weave -destination 'platform=macOS' -derivedDataPath .build/xcode CODE_SIGN_IDENTITY=- CODE_SIGNING_REQUIRED=NO build` 做本地 ad-hoc 签名，保留工程的 App Sandbox 配置。`CODE_SIGNING_ALLOWED=NO` 只用于编译验证；直接运行无签名产物可能改用非容器 Application Support，不能据此判定原笔记丢失。重启按 AGENTS 的单实例规则操作，先核对会话、保存状态与实际数据目录。

## 验收边界

Mac 文字布局调整需检查中文、英文、空段、标题、跨行选择、emoji、代码块首行及表格附件；文字基线和下方段落位置应保持不变。几何回归与实际 App 截图分别记录，原生光标与选区几何通过 TextKit API 检查，并在 App 中验证焦点、移动和闪烁，不用自定义绘制辅助函数作为验收依据。

非首段标题要单独检查段前留白：六级标题在宽窄窗口与折行后，原生光标/选区应包住当前行文字，不能因为规范化行高或基线而漏算段前间距。N01 嵌套样本用于覆盖标题及正文粗斜体/删除线边界。链接检查默认灰色下划线与文字的距离、引用内颜色继承、换行和原生下划线组合；macOS 悬停仅当前链接变为主题色文字与实线，移出平滑恢复、编辑后立即清除，检查快速移入移出连续过渡及减少动态效果设置，装饰间距保持一致，不得改变正文、光标几何或持久化格式。

没有操作证据的项目写“待验证”；模拟器编译不等于模拟器运行，更不等于真机通过。单元测试对 marked text 的布尔保护不等于真实中文输入法通过。截图不等于撤销、保存或选择行为通过。

当前没有 CloudKit。将来同步验收必须覆盖离线修改、不同设备冲突、账号与配额问题、恢复与重试，并记录真实多设备证据。同步不替代备份。

## 持续集成

`.github/workflows/ci.yml` 在每次 PR、main 推送及手动触发时运行，采用 GitHub `macos-26` 镜像和 Xcode 26.2。工具链变更需重新核对覆盖率和 UI 基线；镜像清单见 [GitHub runner-images](https://github.com/actions/runner-images/blob/main/images/macos/macos-26-arm64-Readme.md)。

- `Unit tests and coverage`：运行 Swift 测试与 Python 覆盖率门禁自身测试，保留日志、LLVM JSON 和 Markdown 汇总。
- `UI tests (macOS)` / `UI tests (iOS)`：运行 `WeaveUITests`，保存 `.xcresult`（包含截图）和日志。iOS 自动选择可用的 iOS 26 及以上 iPhone 模拟器，不绑死设备 UUID。
- `CI required`：汇总检查；上游失败、取消或跳过都不能通过。仓库分支保护需要将此检查设为必需；仅添加 YAML 不会自动修改 GitHub 分支保护。

本地单测和门禁：

```sh
swift format lint --recursive --strict --configuration .swift-format Sources Tests UITests Package.swift
swift test --enable-code-coverage
python3 scripts/check_coverage.py "$(swift test --show-codecov-path)"
python3 -m unittest discover -s scripts -p 'test_*.py'
```

行覆盖率下限在 `scripts/check_coverage.py` 集中定义：核心逻辑 90%、原生桥接 55%、全源码 35%。UI 组包含 App 入口、WorkspaceView、MacWorkspaceView、MobileWorkspaceView 、NativeTableView 和 Toast；ToastPresenter 仍归入核心逻辑组。桥接组包含 NativeRichTextEditor、NativeTextAttributes 与 NativeTableOverlay。核心包含除这两组以外的全部 Swift 文件，新增文件默认纳入；当前平台编译的全部文件均计入全源码。报告缺失、源码缺项、重复条目或非法计数直接失败。门槛基于起步实测，不能把全源码 35% 描述成全项目 90%；后续扩大测试后应提高门槛，不因失败自动降低。

Package 单测运行在 Mac，覆盖率脚本默认 `--platform macos`：明确列出且排除整个文件受 `#if os(iOS)` 包裹的 `App/MobileWorkspaceView.swift`；`--platform ios` 对应排除 Mac 专属工作区文件。平台专属映射以完整相对路径列举，其他新增文件仍须有报告。移动端工作区行为由 iOS UI 测试验证，不能将 Mac 单测覆盖率当作它的覆盖率。

当前覆盖率来自单测，不混入 UI 执行数据；不提供分支覆盖率或新增行覆盖率门禁。UI 测试通过是独立检查，也不等于截图像素回归通过。

本地 UI 测试：

```sh
xcodebuild -project Weave.xcodeproj -scheme Weave -destination 'platform=macOS' -derivedDataPath .build/ui-macos -parallel-testing-enabled NO CODE_SIGN_IDENTITY=- CODE_SIGNING_REQUIRED=NO test
xcodebuild -project Weave.xcodeproj -scheme Weave -destination "platform=iOS Simulator,id=$(python3 scripts/select_simulator.py)" -derivedDataPath .build/ui-ios -parallel-testing-enabled NO CODE_SIGN_IDENTITY=- CODE_SIGNING_REQUIRED=NO test
```

添加 `-resultBundlePath` 可保存到尚不存在的 `.xcresult` 路径。Mac UI 测试需要可用桌面与测试自动化权限，会操作测试 App。CI 使用临时宿主；本地不在操作其他 App 时混跑 UI 测试。

每个 UI 测试通过 Debug 专用 `WEAVE_UI_TEST_SESSION` UUID 使用独立的 Application Support/WeaveUITests 子目录；重启同一测试继续读取相同数据，不使用或清理真实 Weave/notes.json。Release 不读取该变量。测试以稳定 accessibilityIdentifier 查找控件；Mac 小屏幕会把工具栏动作收进溢出菜单，首次新建通过空状态主按钮完成，不假设工具栏动作始终可见。截图和文本断言只证明所覆盖场景；真实中文候选、富文本视觉和触控仍按上面的矩阵验证。

## Mac 工作区布局回归

使用隔离 UUID 存储，检查：空库创建分类 → 分类内新建笔记 → 输入标题和正文 → 返回列表 → 全部记录视图 → 搜索标题/正文与无结果 → 移到未分类 → 重启。核对正文与空分类均恢复。分类名称和展开箭头分别验证浏览/展开行为，Command-N 使用当前窗口分类，任务入口显示规划状态。

窗口缩放与侧栏显隐时检查选区、正文和滚动；保存失败须在列表和编辑区均有重试入口。新布局不替代编辑器既有输入、撤销、Markdown、表格与中文组合态验收。

`testMacLibraryFoldersAndSearch` 覆盖主要组织流程，存储测试覆盖旧数组迁移、新快照、空分类与异常数据保护。UI 测试如与用户正在运行的 App 共存，使用独立构建目录及独立 `PRODUCT_BUNDLE_IDENTIFIER`，避免测试启动终止用户实例。浅深色、VoiceOver、真实中文输入法和移动端新导航需要各自操作证据，不能由本轮编译结果推断。

## iOS / iPadOS 工作区回归

检查分类、笔记列表、编辑之间的点击返回和边缘返回手势；分类内新建、移动、搜索、分类重命名与重启恢复。任务页应能返回笔记导航。

iPad 宽窗口检查侧栏与内容同时显示；编辑时旋转、调整窗口宽度和隐藏侧栏，核对笔记、选区与滚动位置。单一视图树不等于所有状态已验收。软键盘打开时检查正文和工具栏可达。

`testMobileLibraryOrganizationAndRestoration` 覆盖分类内新建、编辑、移动与重启；编辑恢复测试在紧凑模式从全部记录进入。`testMobileSearchAndReturn` 覆盖正文搜索、无结果、打开结果及退出搜索后返回总览；`testIPadEditorSurvivesRotation` 在 iPad 验证旋转后正文保留、侧栏可达与继续输入。iPhone 与 iPad 操作分别记录证据，旋转测试不替代分屏缩放、选区与滚动位置的手动验证。

## 记录卡片回归

Mac、iPhone 与 iPad 检查记录首页和分类均使用卡片；点击「记录」回到全部内容，按最近编辑排序。检查无标题、长标题、长正文、空分类和搜索无结果；打开卡片再返回应保留筛选与滚动定位。移动端长按卡片或编辑页菜单完成移动，不再依赖列表轻扫。

瀑布流回归：混合一句话、长标题、无标题、清单和千字长文，检查高度上下限、摘要截断、日期不被挤出；缩放窗口跨越一/二/三列边界时无重叠或横向溢出。`RecordMasonryLayoutTests` 检查最短列填充和多种宽度下的边界与不重叠；实际文字高度、滚动返回、触控和大字号仍需对应平台检查。

收藏能力已移除，不提供收藏入口、卡片星标或操作。

## Markdown 粘贴样本

打开 [markdown-paste-sample.md](examples/markdown-paste-sample.md) 的源码视图，全选复制原始文本，新建记录、进入正文后正常粘贴（Mac Command-V；iOS/iPadOS 使用系统粘贴）。不要复制 Markdown 预览网页的富文本；带 RTF/HTML 的剪贴板优先保持系统格式。样本不含图片或 HTML，下划线需单独从格式菜单设置。

检查六级标题、强调与链接、多级列表、勾选、引用嵌套、三种代码块、两张表格和中英文 emoji；整次撤销/重做、替换包含 emoji 的选区、继续输入、切换记录和重启。再次粘贴后检查两个副本的表格与代码操作相互独立。普通文本应保留原换行，代码内粘贴 Markdown 应保持字面量，选中文字粘贴 URL 仍创建链接。

原生桥接测试直接读取这份仓库样本，验证实际粘贴路径的块语义与标识独立性；平台视觉、系统剪贴板入口、输入法和触控仍需实际操作。

样本的“嵌套组合回归”提供 N01–N10 独立案例：多重强调、标题内格式、格式化链接、引用内标题和列表、三类列表交错、引用内代码块、行内代码字面量、手动下划线组合，以及跨格式 UTF-16 选区。每例附检查重点；粘贴检查之外，按说明执行边界输入、退出、撤销重做和原生格式操作。新增样本文本不等于所有案例已通过人工验收。

## 列表标记与正文选区

### 输入与富文本组合矩阵

`NativeInputTests` 的参数化用例覆盖三类列表的快捷创建、顶层及嵌套空项互转、正文后语法不误触发、0/1/2 级续项、空项回车退出、逐级退格及合并、行中拆分、勾选状态保留、缩进上限、撤销重做、UTF-16 emoji 替换和 marked text 期间不转换。退出空列表应清除其前导 Tab；修改已完成待办的缩进应保留完成状态。

富文本回归包含六级标题创建/回车/行首退格、正文/标题/引用/三类列表内的加粗/斜体/删除线/行内代码快捷输入与后续输入、格式化选区添加链接、行内转换撤销重做，以及引用内列表退出。`MarkdownFormattingTests` 覆盖 72 种段落与行内格式组合的原生桥接及 Markdown 往返、代码中保留语法字面量、下划线与粗斜体/删除线/链接的原生剪贴板往返。下划线没有 Markdown 标准语法，不把 Markdown 往返列作其验收条件。

这些原生输入和几何自动化运行于 macOS。iOS/iPadOS 的软键盘、触控选区与真实中文候选仍需各自操作验证；共享逻辑及平台构建通过不代表所有设备交互已验收。组合矩阵覆盖受支持的代表性组合，不宣称穷尽任意层级嵌套。

无序圆点使用随字号缩放的矢量圆形，有序编号使用系统字体单独绘制，二者都不占正文字符位置。检查正文全选、跨段选择和光标左右移动，标记不进入字符选区；检查单行与折行、中文/英文/emoji、引用内列表与嵌套缩进。正文起点退格先减少缩进、再退出列表，不删除首字；回车续写、空项退出、Tab/Shift-Tab、撤销重做和后续输入均需回归。

旧记录加载前校验原投影，迁移后保存新属性；再次重启应保留内容及编号。Markdown 与应用内剪贴板仍保留列表语义，纯文本剪贴板回退使用 Markdown 标记。主级编号保留每项的值，回车递增；主级任意插入、删除后的整段自动重编号尚未实现。嵌套有序列表根据父项边界重新计数。

多级标记回归：无序前三层依次为实心圆、空心圆、方块，第四层循环；有序前三层依次为数字、字母、罗马数字。每个父项的子序列重新开始，兄弟项递增；检查缩进、减少缩进、引用内列表及 Markdown 往返。编号使用等宽数字并右对齐，文本选区仍不包含标记。样本包含四级有序结构。

列表光标边界：点击缩进区、行首键、左右方向键时，折叠光标不得停在列表前导 Tab 内。正文起点向左跳到上一段末尾；首段起点不越界。退格继续减少缩进/退出列表，跨段选区保留；普通正文和代码内的 Tab 不受限制，组合输入期间不修正选区。

列表快捷输入：在空文档、文末和已有正文前的空段分别输入 `-`、`*`、`+`、`1.` 再按一次空格，立即显示列表标记，光标位于正文起点；不需要第二个空格。继续输入中文/emoji、撤销重做，核对后续段落样式不被改变。

空列表首字几何回归：无序、有序和待办分别在空文档及已有正文前的空段输入快捷语法；比较输入首个中文字前后的标记位置与正文起点，不能出现横移。原生测试同时检查光标、标记的横纵坐标；待办的空项输入属性和换行边界都应立即带上列表缩进。

待办缩进与退格：空待办连续按 Tab/Shift-Tab 后，勾选框、光标和输入首字的位置应一致。非空待办回车续项后，退格先减少当前项缩进，无缩进时取消当前行待办并保留换行；再次退格才允许合并上一行。检查撤销、重做及继续输入正文。

空有序/无序续项：非空项回车后连续 Tab、Shift-Tab，圆点或编号始终可见；只含前导 Tab 的段落不能被当作已绘制标记。输入子项正文后，标记位置与层级保持一致。

## 代码块换行与横向滚动

复制左侧的自动换行按钮默认开启。分别关闭普通和引用内代码块，检查长行不折行、水平滑动仅移动当前块文字、语言与操作栏固定；第二个代码块和正文仍按各自宽度排版。重新开启应回到左端并恢复折行。检查横向与斜向触控板手势、惯性及 Shift+滚轮，正文视口横坐标始终为零，原生 `textContainerOrigin.x` 始终等于阅读内边距，不能随负坐标代码行自动补偿；长行末尾的原生光标自动滚动也不能带动整页。检查长中文/英文、文末光标、缩放窗口后的滚动边界，以及横向滚动后继续输入、选择、复制、撤销。换行是当前编辑视图的临时显示状态，重开记录恢复默认，不改变存储或 Markdown。

`ReadingLayoutTests` 覆盖引用/非引用长行、正文几何隔离、滚动和光标可见、恢复换行、窗口变宽后的偏移钳制与富文本不变。平台编译不能替代真实触控、组合输入和选区拖动验证。


## 代码块高度与纵向滚动

总高度上限 400 pt，包含工具栏和内边距。用 60 行代码、自然折行长行、短代码块、引用内代码和文末开放空行检查：块内上下滚动时工具栏、下方正文及另一块不移动；不换行时两个方向都只影响当前块；短块不预留 400 pt。滚动条仅滚动时显现，停止后淡出。

键盘跨越可见边界时逐行移动，不能跳过隐藏行；覆盖向上/向下、Shift 扩选、从正文进入代码、文末空行回车、删除和撤销。缩放窗口、恢复换行及删除大段内容后偏移必须收回有效范围。点击滚动后的文字应落在对应字符上，存储与 Markdown 不包含视口偏移。

`ReadingLayoutTests` 检查高度、正文几何隔离、原生点击命中、原生上下方向键、引用/非引用宽度变化与删除回缩、文末空行和数据不变。Mac App 已检查长短块显示、末行光标自动显示、跨视口逐行向上移动，以及滚动后输入与撤销；真实触控板手势因自动化工具找不到窗口尚待操作验证。移动端构建不代表触控、惯性、外接键盘与输入法已验收。


代码行号回归：普通/引用内代码、多块重置编号、连续空行、软折行、文末开放空行，以及 9→10、99→100 行时的宽度变化。横向滚动只移动文字，行号保持固定；纵向滚动后编号对应真实源代码行。点击编号区应映射到该行文字边界，复制和导出不含行号；检查空行输入首字前后的光标对齐及撤销。`ReadingLayoutTests` 覆盖源代码行计数、折行不重复、块间重置、编号与正文间距、横向位置固定、纵向末尾编号、三位数宽度和富文本不变。


展开与溢出提示：短块无展开入口，纵向溢出块显示“展开全部”；展开后全部代码可通过文档滚动查看，工具栏变为“收起”，收起恢复 400 pt 和顶部位置。检查独立代码块、自然折行、引用内代码、切换换行及编辑后溢出状态更新；展开不改动数据、复制内容或撤销历史。代码边缘不显示渐变，保留滑动时出现的滚动条；浅深色、窄屏与移动端实际效果分别核查。`ReadingLayoutTests` 覆盖双轴滚动边界、展开高度、收起恢复、短块判断和存储不变。

Mac 展开/收起实际操作已检查：按钮留在原位、圆角与顶部留白保持、收起后下方正文恢复原位置。原生 `textContainerOrigin` 两个方向均保持配置内边距，不能因首行工具栏或横向负坐标自动补偿。移动端实际操作仍待验证。

代码缩进：Tab 插入 2 个空格，Shift-Tab 移除最多 2 个空格或一个 Tab；覆盖空块、末尾空行、多行选区、中文和 emoji、撤销与重做。旧代码不自动重排，回车沿用当前行已有缩进。


代码语言和格式化回归：检查支持语言切换后显示格式化按钮，Swift/Python/未知语言/plain text 隐藏；按钮位于复制左边，悬停手型，具有“格式化代码”辅助标签。逐个验证 12 个格式化语言入口、2 空格、中文和 emoji、重复格式化幂等、尾部 LF 不增加正文空段。JSON 大整数、重复键保留；语法错误保留原文并显示错误。NativeInputTests 覆盖相邻正文/代码块、外部选区、撤销重做、编辑与改语言后的过期结果拒绝。移动端实际点击、中文组合输入和 VoiceOver 仍需设备验收，不能以构建通过替代。
